# Deadman Demo Script (90 seconds)

This video is for Solana Mobile CLOCK IN (due 2026-10-08) and is reused for the Colosseum World's Fair submission. Everything is shot on devnet with real transactions, on the Solana rail. The private rails (Cloak, Zcash) and Earn only work in a mainnet build, so they are not in this video.

## Setup (off camera)

- **Config on devnet.** Run `KEYPAIR=<upgrade-authority.json> scripts/devnet_setup.sh` once after deploying, so the release fee is 2% on both rails (1.5% for SKR payouts, 10% of it burned). If Config already exists, run `dart run tool/set_config.dart --keypair <admin.json>` (defaults 200 / 200 / 150 bps, 1000 bps burned); on the old 77-byte devnet Config this run is also the required migration.
- **Phone A (owner):** a Seeker with the devnet APK (`flutter build apk`, no `CLUSTER` define) and Seed Vault Wallet on devnet. Arm a vault in the release-plan editor:
  - **Demo timings: on**, lock 300 s. There is no check-in interval: each tier's wait after the last pulse is its whole timer (the program accepts 60 s and up).
  - **Tier 1:** phone B's wallet, Solana rail, after **3 min** (Custom, minutes), **50%** of SOL.
  - **Tier 2:** phone B's wallet, Solana rail, after **6 min** (Custom, minutes), **100%** of SOL, i.e. whatever is left.
  - **Deposit:** 1 devnet SOL.
  - **App PIN and a different duress PIN.**
- **Phone B (beneficiary):** a second Android device or an emulator running the same app, connected to the beneficiary wallet. Give it about 0.05 devnet SOL if the beneficiary will release the tier themselves.
- **Laptop:** the vault address open in Solana Explorer (devnet), and the keeper in a terminal: `dart run tool/keeper.dart --keypair <funded devnet keypair> --every 10`.
- **Choose who releases tier 1, and film only that path:**
  - **Keeper (default).** Keep the keeper running. It executes tier 1 within about 10 s of it falling due.
  - **Beneficiary.** Stop the keeper before beat 3, and have phone B tap "Release this tier" when it appears.
- **Shoot it as one continuous take** of about 4 to 5 minutes, then edit it down to 90 s with jump cuts. Keep the in-app countdown or a wall clock in frame across every cut, so viewers can see the wait was real.
- Do not tap Pulse or perform any owner action between beat 3 and the tier 1 release. Any of them resets the clock. The attacker's withdrawal in beat 5 sends no transaction at all, so it does not count.

Timeline from the Pulse in beat 3 (T): lockdown at about T+20 s, locked until about T+320 s; tier 1 due after T+180 s; tier 2 due after T+360 s unless the owner pulses again.

## Checks before recording

- The `Config` PDA on devnet must have `fee_bps_public = 200` (run `tool/set_config.dart` once after the deploy; it also migrates the old Config, without which every payout fails), so the fee line shows up in the payout. Make the figures on screen match: 50% of 1 SOL is 0.5 SOL gross, 0.49 SOL to the beneficiary and 0.01 SOL to the treasury.
- The treasury account already holds SOL (by default it is the admin wallet). If it were empty and the fee too small for rent, the program would give the fee to the beneficiary instead.
- The duress PIN path really signs `lockdown` with the guard key. Confirm in the explorer that the `LockedDown` event's `by` field is the guard key.
- The keeper keypair is funded on devnet and the keeper prints its address and "scanned N vaults" on start.
- The final Pulse happens before T+360 s, or tier 2 will release too.
- Only claim on camera what the build does on camera. Do not show a Cloak or Zcash tier releasing or routing on devnet; the end card mentions them as mainnet features only.
- Before saying "open source," make sure the GitHub repository is public.
